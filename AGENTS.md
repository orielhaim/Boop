# Working on Boop

- Run `bun install --frozen-lockfile`, `bun fmt .`, `bun run lint`, `bun run typecheck`, and `bun test`. Use a development build for native modules. Skip iOS build, runtime validation, host discovery, and connection attempts.
- Before changing Expo or React Native APIs, read the installed Expo major in `package.json`, the [matching SDK reference](https://docs.expo.dev/versions/v58.0.0/), and the [Expo documentation index](https://docs.expo.dev/llms.txt). Use `bunx expo install` for Expo packages.
- Put Expo Router routes in `src/app`, shared UI in `src/components`, and generated native configuration in `app.json` and `plugins`. Keep Chats, People, and Profile at the tab root. Open Settings from Profile and use the shared person route.
- Open [Development](DEVELOPMENT.md) for builds, database resets, and native fixtures. Preserve Drizzle's configuration and generated migrations. Keep Fumadocs for the website. Follow the [design system](DESIGN-SYSTEM.md) for UI, localize app copy in English and Hebrew, and check LTR and RTL.
- Compose the protected account session in `src/services/local.ts`. Keep its Marmot lifecycle separate from relay and call signaling. Store Boop-owned durable state in `src/db`, with separate SQLite databases per account and a public account selection.
- Open Welcome when MarmotKit has no account. Use MDK's generated-account API, checkpointed import, platform keyring, and native signer. Keep reviewed secrets native and authenticate raw export. Retire the old account after the replacement is ready. Use independent device-only keys for encrypted download records and transcripts.
- Keep device trust in MDK. Use one controller per protected account and retire access on native unlink even during App Lock. Open [Account devices](DEVELOPMENT.md#account-devices) for pairing, device commands, and removal.
- Read membership, delivery, and history through MarmotKit windows with opaque IDs. Use installed Chat Kit APIs and MDK client tokens. Verify signed kind 0 profiles and keep local contact overrides in contact preferences. Use checked native transport for NIP-05 and profile images.
- Keep call signaling in `src/core/calling/signaling-service.ts`. Encrypt kind `24880` with NIP-44/NIP-59. Verify the Seal before checking caller blocks. Use relay inbox discovery for first contact and subscribe to expiring MLS call announcements separately from history. Recheck authorization at dispatch, admission, and peer authentication.
- Bind authenticated peer identity to DTLS fingerprints before microphone access. Keep one audio lease and capture per call. Send conference video only to viewers who opted in. Keep saved contacts, invitation approvals, successful local initiation, and video consent independent.
- Use MarmotKit for encrypted attachment drafts, transfer, verification, and retention. Keep metadata in the encrypted event and render authenticated previews and verified local leases. Fetch received attachments only after an explicit Download action on a live accepted message.
- Apply avatar privacy independently. Require a tap for On Demand previews. Limit automatic previews and translation to eligible visible messages in a focused, foreground, unlocked chat. Preserve original message bytes separately from derived text.
- Transcribe verified retained Marmot voice notes on-device through the protected speech queue. Seal transcripts and timings. Check Open Later on conversation open and paging, verify before storing plaintext in the account cache, and keep decryption off the background scheduler.
- Use Luna for independent exploration, implementation, or review when useful. Give each agent a distinct scope and verify its work before integrating it.
